# Reference app: data layer (`/mnt/data/academy-system-desktop`)

## 1. Database, migrations, SQL transport

- **Engine**: SQLite through `sqlx 0.8` (`src-tauri/Cargo.toml:53-59`). `tauri-plugin-sql` is deliberately not used (`src-tauri/src/db.rs:1-13`).
- **File**: `app_data_dir()/academy.db` (`database_path`, `db.rs:62-70`); identifier `com.hamawebdev.academy-manager` (`tauri.conf.json:5`), so on Windows `%APPDATA%\com.hamawebdev.academy-manager\academy.db`. The name is hard-coded again in `backup.rs:52,84,91`.
- **Opened by Rust only**, inside `setup`, before any window exists (`lib.rs:198-207`). `db::init` (`db.rs:74-98`): `create_if_missing`, `foreign_keys(true)`, WAL, `synchronous=Normal`, `busy_timeout` 10 s, pool `max_connections(1)`; kept as managed state `Db(SqlitePool)`.
- **Migrations**: `sqlx::migrate!("./migrations")` (`db.rs:93`), embedded at compile time, forward-only numbered `.sql` files. A failure hits `.expect("failed to initialise the database")` (`lib.rs:205-206`): a panic, no user message.
- **Transport**: Kysely compiles SQL in the webview; `TauriSqliteDialect` (`src/lib/db/dialect.ts`) calls raw `invoke("db_execute" | "db_select", { sql, params })` (`dialect.ts:57,65`). `isMutation()` prefix test without `RETURNING` goes to `db_execute`, everything else to `db_select` (`dialect.ts:31-67`). Parameters are `SqlValue`, an untagged enum `Null | Bool | Int(i64) | Real(f64) | Text` (`db.rs:30-38`): **no BLOB parameter**. Rows return as JSON objects keyed by column (`row_to_json`, `db.rs:122-159`); `i64` arrives as JS `number` (`lib.rs:137-143`).
- **Transactions**: `BEGIN` / `COMMIT` / `ROLLBACK` are separate IPC calls (`dialect.ts:106-119`). They are atomic only because Rust has one connection and `TauriDriver.acquireConnection` is a promise queue (`dialect.ts:82-96`). No savepoints, isolation levels or streaming.

Commands (registry `lib.rs:38-51`); all open with `license::guard` except the three licence ones:

| Command | Signature | Where |
|---|---|---|
| `db_select` | `(sql: String, params: Vec<SqlValue>) -> Result<Vec<serde_json::Value>, CommandError>` | `db.rs:165` |
| `db_execute` | `(sql, params) -> Result<ExecuteResult{rows_affected: u32, last_insert_id: i64}, CommandError>` | `db.rs:184` |
| `db_checkpoint` | `() -> Result<(), CommandError>` (`PRAGMA wal_checkpoint(TRUNCATE)`) | `db.rs:206` |
| `db_path` | `() -> Result<String, CommandError>` | `db.rs:218` |
| `backup_to` | `(target: String) -> Result<(), CommandError>` | `backup.rs:46` |

| `license_status` | `() -> LicenseStatus` | `license/mod.rs:257` |

`CommandError { message }` (`lib.rs:12-14`). `src/lib/bindings.ts` is generated by tauri-specta (debug build or `cargo test export_bindings`, `lib.rs:131-147,236`); only the licence UI imports it. The DB path and `src/server/actions/backup.ts:50-51,69-70` use raw `invoke`.

## 2. Recipe for a new entity

1. `prisma/schema.prisma`: add the model. It is a **type source only**, parsed as text by `scripts/generate-db-types.mjs:21-58`; Prisma is not installed (`package.json`).
2. `npm run db:types` regenerates `src/lib/db/schema.ts` (Kysely `DB`, raw storage types), `models.ts` (app shapes: `Date`, `boolean`), `column-meta.ts` (`DATE_COLUMNS`, `BOOLEAN_COLUMNS`). Never hand-edit.
3. `src-tauri/migrations/000N_*.sql`: hand-written matching DDL (type map `0001_init.sql:7-12`). Nothing checks it against step 1.
4. `scripts/verify-db.mjs:32`: the migration list is a hard-coded two-item array; add the new file.
5. `src/lib/validators/<entity>.ts`: zod schema, `as const` enum arrays, inferred `FormValues`.
6. `src/server/actions/<entity>.ts`: plain async functions running in the webview. Pattern (`employees.ts`): `requirePermission(module, action)` gives `session.user.id`; query `db` from `@/server/db`; `hydrate` / `hydrateAll("<Table>", rows)` on the way out; inserts supply `id: newId()`, `createdAt` / `updatedAt: nowIso()`, dates through `toDbDate`, booleans as `? 1 : 0`; multi-statement work in `db.transaction().execute(async (tx) => …)`; return `{ success: true } | { success: false, error: "English sentence" }`; finish with `revalidatePath("/dashboard/<entity>")`.
7. `src/messages/{en,ar,fr}.json`: every new English error sentence under `Errors` (`src/i18n/errors.test.ts` fails otherwise).
8. `src/pages/dashboard/<entity>/page.tsx`: `useQuery({ queryKey: pathKey("/dashboard/<entity>"), queryFn })` (`employees/page.tsx:16-19`). Forms: `zodResolver(schema)`, `createJsonFormData` + `appendOptionalFile` / `appendBooleanFlag` (`src/lib/form-submission.ts`) parsed by `parseJsonFormData` / `getOptionalFile` (`src/server/form-data.ts`).
9. `src/routes.tsx` (hash router), `src/navigation/sections.ts`, `DASHBOARD_MODULES` in `src/lib/permissions.ts`, and `UploadEntity` / `UploadField` in `src/server/uploads.ts:26-27` if it has files.

**Cache contract**: global `staleTime: Infinity` (`src/lib/query-client.ts:14`), so nothing refetches unless invalidated. `revalidatePath(path)` runs `invalidateQueries({ queryKey: pathKey(path) })`; `pathKey` splits on `/` (`src/lib/compat/revalidate.ts:15-27`). Matching is by prefix, so sub-queries use `[...pathKey(path), "suffix"]`. Aggregate pages spread `AGGREGATE_QUERY_OPTIONS = { staleTime: 0 }` (`query-client.ts:42`). Non-path keys invalidated by hand: `["settings"]`, `["branding"]`, `["levels"]`, `["academic-years"]`, `["qr-token", role, id]`.

## 3. Schema in brief (37 tables, `0001_init.sql`)

- Foundation: `User` (the one local academy row; branding `name`, `academyName`, `logoUrl`; leftovers `email`, `password`, `role`, `parentAdminId`, `permissions`, `accessStartDate/EndDate`), `AcademicYear`, `Term`, `Level`, `Program`, `Setting` (`key`, `value`).
- Students: `Student` (about 65 columns, `photoUrl`), `Enrollment` (`status`), `StudentAttendance`, `Observation`, `ProgramTracking`, `PolicyDocument`.
- Staff: `Teacher`, `TeacherLevelAssignment`, `TeacherProgram`, `TeacherCheckRecord`, `TeacherAbsence`; `Employee` (`jobPosition`, contract fields, `cvUrl`, `photoUrl`, `isActive`), `EmployeeCheckRecord` (`type`, `timestamp`), `EmployeeAbsence` (`type`, `absenceHours`).
- Money: `Payment` (`amount`, `sessionsAdded`, `debtSessionsAtRenewal`, `type`), `TeacherIncomeReset` (`amount`, `balanceBefore`), `TeacherDebtLedger` / `EmployeeDebtLedger` (`type`, `amount`, `balanceAfter`), `EmployeePayout`, `Expense` (`category`, `date`, `amount`, `receiptUrl`).
- Groups and rooms: `Group` (`teacherIncomePercent`, `pricePerSession`, `totalSessions`), `GroupStudent`, `GroupAttendance`, `ClassroomSchedule`.
- Rent: `RentTeacher`, `RentGroup`, `RentPayment`, `RentSession`, `RentTeacherAbsence`, `RentTeacherCheckRecord`. Also `QrToken`.
- Outside migrations: `_license(key, value)`, created by `license/vault/db.rs:68` on its own connection.

Conventions:
- Quoted PascalCase tables, camelCase columns.
- **Ids**: `TEXT PRIMARY KEY`, `crypto.randomUUID()` via `newId()` (`src/lib/db/rows.ts:77-79`); seeds use fixed slugs.
- **Timestamps**: TEXT ISO-8601 UTC, written from JS by `nowIso()`; no triggers, no DB defaults. Trap: `schema.ts` types `id`, `createdAt`, `updatedAt` as `Generated<>` (from Prisma `@default`) but the DDL has no `DEFAULT`, so omitting them compiles and then fails `NOT NULL`.
- **Booleans**: INTEGER 0/1.
- **Soft delete**: `deletedAt` + `version` on most entity tables, filtered by hand in every query; cascades are hand-written transactions (`employees.ts:316-334`). `version` is only incremented on soft delete (25 sites) and never checked: a sync leftover. Hard deletes: `Expense`, `RentPayment`, `TeacherLevelAssignment`. No `deletedAt` on ledgers, `Payment`, `Setting`, lookups.
- **Enums**: plain TEXT, no CHECK constraints; values live in zod arrays (`JOB_POSITIONS`, `validators/employee.ts:15-25`; `PAYMENT_TYPES`, `validators/payment.ts:3`). The Prisma file has 0 `enum` blocks.
- **Money**: `REAL` (float dinars), not minor units. Cent rounding is done in JS (`moneyToCents`, `roundMoney`, `sumMoney`, `src/lib/finance/calculations.ts:42-58`), used only by `finance.ts`; `payments.ts:159-165` compares with a `0.01` epsilon.
- **Academy-specific**: `adminId` on 12 tables, `academicYearId`, `termId`, `educationLevel`, `stream`, levels, programs.

## 4. Settings and first run

- **`Setting` table**, not the Tauri store: `getAppSettings` / `saveAppSettings` (`src/server/actions/settings.ts:33-71`), keys limited by `SettingKey` (`manager_password_hash`, `manager_recovery_hash`, `locked_pages`, `classroom_count`), cached as `SETTINGS_QUERY_KEY = ["settings"]`, hooks in `src/hooks/use-settings.ts`. Upsert per key on `(adminId, key)`, no transaction.
- Branding lives in the `User` row (`src/server/branding.ts`, `actions/branding.ts`). Theme is `localStorage` (`src/lib/preferences/preferences-config.ts`). Locale persistence: not examined.
- `tauri-plugin-store` is registered (`lib.rs:189`, `store:default`) but has **no import in `src/`**: unused.
- **No setup wizard.** `getSetupStatus()` (`actions/setup.ts`) has no callers. First run is: create the file, run `0001`, run `0002_seed.sql` (`local-admin` user, 4 levels, 7 programs, current academic year, 3 terms), then `license::evaluate(app, db_existed)` starts the trial (`lib.rs:198-223`).

## 5. Uploads

- Stored at `{appDataDir}/uploads/{adminId}/{entity}/{field}/{uuid}.{ext}` by `saveManagedUpload` (`src/server/uploads.ts:69-104`) using `@tauri-apps/plugin-fs`, scoped to `$APPDATA/uploads/**` (`capabilities/default.json:17-37`).
- The DB column (`photoUrl`, `cvUrl`, `receiptUrl`, `logoUrl`) holds the web-era string `/api/uploads/{adminId}/{entity}/{field}/{file}` (`MANAGED_UPLOAD_PREFIX`, `src/lib/uploads.ts:3`).
- Display: `useUploadSrc` (`src/lib/use-upload-src.ts`) calls `resolveUploadSrc`, which uses `convertFileSrc` (asset protocol, scope in `tauri.conf.json:37-40`); the `Image` shim in `src/lib/compat/image.tsx` wraps it. PDF viewing branch at `expenses-table.tsx:165`; exact viewer unsure.
- Rules: photo 10 MB, logo 5 MB (jpg/png/webp), CV PDF 20 MB, receipt 20 MB (`src/lib/uploads.ts:11-33`).
- The file is written before the row and removed if the insert fails; soft-deleting an employee deletes its files (`employees.ts:337`). Backup copies them to a sibling `<stem>-uploads/` folder (`backup.rs:37-40`).

## 6. Audit log, history, numbering, void

**None.** No audit table, no change history, no sequence or document-number helper, no void pattern (grep over `src/server`, `src/lib/db`, migrations). Ledger tables are insert-only by convention only. `addEmployeeDebtEntry` reads the latest `balanceAfter` and then inserts **outside a transaction** (`src/server/actions/employee-payments.ts:118-137`), ordered by `createdAt` text. Receipts carry no number.

## 7. Error handling

- sqlx errors become `CommandError { message: error.to_string() }` (`db.rs:47-53`); the invoke promise rejects with that object.
- `src/server/db-errors.ts` regex-matches the SQLite text: `isUniqueViolation(error, column?)`, `isForeignKeyViolation`, `isNotNullViolation`. Actions turn these into English sentences in `{ success: false, error }` (`employees.ts:182-184`) or rethrow.
- `useErrorMessage()` (`src/i18n/errors.ts:95-120`) matches the English sentence against `en.json` `Errors` values (placeholders become regex) and renders the same key in the active locale; unknown messages use the caller's fallback (`employee-form.tsx:140`). `zodErrorMap` (`errors.ts:142-190`) is installed in `src/main.tsx:24`.

## 8. Tests

- `npm run db:verify` (`scripts/verify-db.mjs`): `node:sqlite` on a temp file, applies both migrations, drives real Kysely through a hand-copied driver; checks seeds, date/boolean storage, joins, EXISTS, upsert, transaction rollback and commit, foreign keys. It does not cover the IPC bridge or any action.
- `npm test` (vitest, node, `src/**/*.test.ts`): `src/lib/finance/calculations.test.ts` (pure money maths) and `src/i18n/errors.test.ts` (scans actions and validators for untranslated errors); the rest are licence, navigation, messages.
- Rust: licence tests and `export_bindings` only; none for `db.rs` or `backup.rs`.
- CI: lint, format check, `tsc`, test, `db:verify` (`.github/workflows/ci.yml:17-22`).
- Actions import the Tauri-bound `db` directly, so they cannot run under vitest; the only seam is functions that take an `executor: Kysely<DB>` (`payments.ts:25-30`).

## 9. Permissions and tenant

Leftovers from the multi-tenant web version. `can()` always returns `true` (`src/lib/permissions.ts:34-36`); `requirePermission` just returns `LOCAL_SESSION` (`src/server/permissions.ts:18-27`, `src/server/tenant.ts:27-41`); `LOCAL_ADMIN_ID = "local-admin"`; `assertNotExpired` is a no-op (`tenant.ts:56`). Queries still filter `adminId = session.user.id`. Real gates today: Rust `license::guard`, and an optional manager password with `locked_pages` (PBKDF2 hashes in `Setting`, `src/lib/auth.ts`), which is a UI gate, not data-layer enforcement. No users, no roles, no "who did it".

## 10. Risks for about 60 tables and hash-chained, append-only records

1. **Arbitrary SQL from the webview.** `db_select` / `db_execute` run any statement, CSP is `null` (`tauri.conf.json:36`), and every rule lives in TypeScript. Append-only needs SQLite triggers (`BEFORE UPDATE/DELETE … RAISE(ABORT)`) and, better, a dedicated Rust command that reads the previous hash, computes and inserts inside one Rust-side transaction.
2. **Transactions span IPC round trips.** A webview reload or crash between `BEGIN` and `COMMIT` leaves the single Rust connection inside an open transaction; no recovery code found (behaviour unsure). The licence module also writes through a second connection (`vault/db.rs:35`).
3. **No ordering primitive.** UUID ids and JS-clock timestamps cannot order a chain; add an integer sequence. The existing ledger read-then-insert race (section 6) must not be copied.
4. **Money is REAL.** Use INTEGER minor units; `i64` to JS `number` is exact up to 2^53.
5. **No BLOB parameters**: store hashes as hex TEXT. Hashing in JS over hydrated rows (Date, float formatting) is fragile; canonicalise in one place.
6. **Three unlinked sources of truth** (Prisma file, SQL, generated TS) with a regex parser that ignores enums and `@map`, plus the `Generated<>` mismatch. Drift is silent and grows with table count.
7. **`ON DELETE CASCADE` on money rows** (for example `Payment.groupId`, `0001_init.sql:626`; ledgers to teacher or employee) lets a parent hard delete erase records. Use `RESTRICT`. No enum CHECKs.
8. **Backup and restore.** A raw `std::fs::copy` follows a checkpoint made in a separate call (`backup.ts:50-51`); restore overwrites the live file under an open pool with no validation (`backup.rs:84-95`); a backup from a newer schema would fail migration and panic. Restoring an old backup silently rewinds a chain unless its head is anchored outside the DB; the licence vault (`license/vault.rs`) is the in-repo precedent.
9. **Scale.** One connection, every query a JSON IPC call, lists fetched at `perPage: 200` and filtered in the client, `lower() LIKE` search with no Arabic normalisation (`src/server/sql-filters.ts`), hand-written soft-delete filters and cascades, and no action-level tests.
