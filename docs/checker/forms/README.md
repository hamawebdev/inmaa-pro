# Layout facts for his six Word forms

What a builder needs to print each form as his Word file prints it. Kept by the Checker.

Everything here is read from the XML inside the `.docx` files. This machine has no Word and no LibreOffice, so nothing was seen rendered. A fact that depends on Word's rendering is marked **estimated**; the list is at the end of this page.

Each form file has the same twelve sections: source, page, letterhead, type, glyphs, order of blocks with the page estimate, text boxes, paragraphs, tables, ☐ sides, notes for builders, what is estimated.

## Rules in force for print

- Print reproduces what his Word file prints: the letterhead and footer at their placed size, stretched as placed; his label strings with their stretching characters; the numbers Word generates in front of labels, slips included.
- The only corrections are those of scope A8: «مسأجر» becomes «مستأجر»; «تنظيف غ..الضيوف» stays as typed.
- Printed forms are always Arabic. On screen, labels drop the stretching character.
- Every oddity is recorded on its row in `docs/checker-table.md` so that the developer can rule on it later.

## How to read the files

- **Units.** Millimetres, with the raw value beside them where it matters. 1 twip is 1/1440 inch; 1 pt is 20 twips; border sizes in the XML are eighths of a point.
- **Ids.** `T1.r2.c1` is table 1, row 2, cell 1. `P2` is the second body paragraph, empty ones counted; `P2.box` is the text box anchored to it. The Source column of `docs/checker-table.md` uses the same ids, and section 9 of each form file names the table rows that come from each cell.
- **Right to left.** Tables list their columns and cells in file order, which is right to left on paper: column 1 and cell `c1` are the rightmost. "Alignment on paper" is the side as printed; the XML value is beside it in brackets because the two differ: in a right-to-left paragraph `jc=left` puts the text on the right and `jc=right` on the left.
- **Raw text.** The "Content, raw" and "Text, raw" columns keep his characters, the stretching character (tatweel, U+0640) included. A run of dots is shown as `……`; the exact runs are in the JSON. `⏎` is a line break inside a paragraph, `¶` a new paragraph inside a cell.
- **Numbers in square brackets** such as `[1-]` or `[3.]` are generated by Word's list numbering. They are not in the text and must be printed.
- **Type.** For right-to-left text Word applies the complex-script font, size and weight, and those are the values shown. They can differ from the plain values in the same run: the worker title is 20 pt though its plain size says 14.
- **Blanks** are rows of full stops in the file. Draw each as a dotted line that fills its cell.
- **Options** are typed on one line and spaced with spaces. Their order and the side of each ☐ are facts; the gaps between them are not.

## Fonts

His files name Traditional Arabic, Sakkal Majalla and Arabic Typesetting for text, MS Mincho for most ☐, Times New Roman and Symbol in a few places. None is installed on this machine (it has Noto Naskh, Noto Kufi and Noto Sans Arabic and DejaVu). They are Microsoft fonts: on the client's Windows PC they are used when present; on Windows 10 and 11 the three Arabic ones belong, as far as the Checker recalls and without having checked it here, to an optional feature (Arabic Script Supplemental Fonts), so they may be absent. They cannot be bundled. With the program's own Arabic font the line heights change, so rows and page breaks move; build with fixed widths and minimum heights in millimetres, not with font-dependent sizes.

## What is estimated

- E1. The number of pages and where each page ends (section 6 of each form). Word's recorded count is file metadata; the reading comes from the saved row heights and assumed line heights.
- E2. Every vertical position on the page: the top and bottom of the letterhead and footer pictures, where the body starts under the letterhead, where a text box or a floating table lands.
- E3. What a printer clips near the paper edges (K4).
- E4. The distance of each table's edges from the paper edges. Computed with Word's rules for a Word 2007 file: a centred table (`jc=center`, or floating with `tblpXSpec=center`) is centred on the text area and its `tblInd` is ignored, because Word indents only a table aligned to its leading edge; a table aligned to its trailing edge stands against that margin; a table aligned to its leading edge puts the text of its first cell at the indent, so its border stands out by the cell padding (1.9 mm). With these rules every table of the five client forms has its right edge 7.3 to 7.4 mm and its left edge 10.1 to 10.2 mm from the paper edges, so they line up one under another. Not seen rendered.
- E5. Printed row heights. The file gives a minimum per row; the printed height depends on the fonts.
- E6. The spacing between options in a cell: it is typed with spaces.
- E7. The numbers in front of labels: computed from `numbering.xml`, not seen printed.
- E8. "Alignment on paper": Word's rule for right-to-left paragraphs applied to the XML value.
- E9. Glyph shapes and line heights. None of his fonts is installed here, and Word's substitutes for missing glyphs (☐ in Traditional Arabic runs, the emoji) are not recorded in the file.

**How the page estimate is made.** Each row is taken as the larger of its saved minimum height and its content: lines × type size × a line factor × the paragraph's line spacing. The factors are assumptions: 1.57 for Traditional Arabic, 1.41 for Sakkal Majalla, 1.2 for Arabic Typesetting, 1.22 otherwise. Running text is wrapped at an assumed 0.36 em per letter and 0.25 em per space. The result agrees with Word's own count for the worker form (3.9 body heights against 4 pages, and the page-break marker Word left falls where the estimate starts page 3) and runs about 8% high for the building contract (3.2 against 3). For the four home and organisation forms Word records 1 page. That cannot be right: with a factor of 1.0 and no wrapping they still need 1.3 to 1.5 body heights. They are read as two pages.

**If PDFs saved from Word arrive**, correct in one pass: the page count in section 1, the last row of the table in section 3, the whole of section 6, the positions in sections 7 and 9 marked estimated, `00-letterhead.md`, and `differences.md` section 4. The reading in section 6 is written in `../tools/form_notes.py`.

## Rebuilding and checking

Run from the project folder. The tools use the Python standard library only and write nothing into `client docs/`.

| Command | What it does |
|---|---|
| `python3 -I docs/checker/tools/validate_table.py` | Compares every string of `docs/checker-table.md` with the Word XML and the plan, and the data files with a fresh extraction. Exit status 0 when all checks pass |
| `python3 -I docs/checker/tools/build_forms.py` | Rewrites the form files, `00-letterhead.md`, `differences.md`, the JSON and the two pictures. Safe to rerun; never edit those files by hand |
| `python3 -I docs/checker/tools/build_table.py` | Wrote the first version of the table. It refuses to run again over the table, which is kept by hand from now on |

This page is the only hand-written file in this folder.
